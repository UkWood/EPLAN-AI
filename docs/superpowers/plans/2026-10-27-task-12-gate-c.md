# Task 12 / Gate C MCP Write Surface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the approved Function Text preview/apply/undo workflow through MCP and prove Gate C on a disposable EPLAN 2.9.4 project.

**Architecture:** MCP remains the owner of immutable Change Plans. Preview uses the existing read-only planner; apply accepts only a plan ID and builds the fixed internal `change.apply` request from stored plan state; undo accepts only the current project session and delegates to fixed internal `change.undoLast`. AddIn remains the only EPLAN mutation boundary.

**Tech Stack:** .NET 8 MCP server, ModelContextProtocol, shared Contracts, named-pipe bridge, .NET Framework 4.7.2 AddIn/LegacyHost, xUnit v3 / Microsoft Testing Platform, PowerShell 5.1 workstation scripts.

**Spec:** `docs/superpowers/specs/2026-10-27-task-12-gate-c-design.md`

## Global Constraints

- Exactly three new model-callable tools: preview, apply, undo.
- Apply model input is `changePlanId` only.
- Undo model input is `projectSessionId` only.
- No arbitrary property IDs, action names, bridge operations, paths or code.
- MCP references no EPLAN assembly.
- A claimed Change Plan is never made retryable after an uncertain apply outcome.
- Gate C real mutation uses only a disposable/safe project with an explicit safety guard.
- Do not merge without explicit user approval.

## Review Focus

- malformed/empty plan IDs must fail before bridge mutation;
- plan with wrong operation count/kind must fail closed and be terminal after claim;
- bridge failure after claim must mark the plan failed, including thrown transport/MCP exceptions;
- preview must remain EPLAN-read-only even though it creates local in-memory state;
- undo must not accept caller-controlled target or reverse values.
