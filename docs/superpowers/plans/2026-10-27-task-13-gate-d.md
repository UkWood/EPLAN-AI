# Task 13 / Gate D v0.1 Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a reproducible EPLAN AI Bridge v0.1 release bundle, installation/troubleshooting/security documentation, and a repeatable Gate D verifier without changing the approved EPLAN runtime surface.

**Architecture:** Keep real EPLAN compilation separate from pure packaging. A testable PowerShell packaging helper builds component/combined ZIPs and checksums from already-built directories; a workstation orchestrator alone certifies release binaries by rebuilding AddIn/LegacyHost against real EPLAN 2.9.4 and publishing MCP before invoking the helper. Security verification is a separate static guard backed by positive/negative fixture tests.

**Tech Stack:** Windows PowerShell 5.1, .NET Framework 4.7.2, .NET 8, GitHub Actions, EPLAN 2.9.4 API assemblies.

**Spec:** `docs/superpowers/specs/2026-10-27-task-13-gate-d-design.md`

## Global Constraints

- Release version is exactly `0.1.0`; planned tag is `eplan-ai-bridge-v0.1.0`.
- Release output is under ignored `artifacts\release\eplan-ai-bridge-v0.1.0`.
- AddIn and LegacyHost release builds must use real EPLAN 2.9.4 assemblies, never CI stubs.
- MCP publish is `win-x64`, framework-dependent, .NET 8.
- All Task 13 scripts must parse under Windows PowerShell 5.1.
- No new MCP tool, EPLAN write target, arbitrary property/action/path/code surface, or network listener is allowed.
- No merge to `main` and no release tag without explicit user approval.

## Review Focus

- Packaging a directory that lacks the component's primary binary must fail rather than produce a partial archive; Task 1 tests this.
- Archive/checksum ordering must be deterministic across repeated packaging runs; Task 1 tests sorted names and exact checksum coverage.
- The AddIn staging directory must not contain redistributed EPLAN AF/Base/DataModel/HEServices DLLs; Task 3 enforces this before packaging.
- The security verifier must reject an introduced TCP listener/dynamic code execution/generic model-controlled path concept while accepting the current closed-world source; Task 2 tests both directions.
- A workstation release attempt with a missing/incorrect EPLAN API directory or a running EPLAN/LegacyHost must fail before producing artifacts; Task 3 tests/implements fail-closed guards.
